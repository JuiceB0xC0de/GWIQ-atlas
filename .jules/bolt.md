## 2024-05-15 - [Vectorizing Array Reductions]
**Learning:** In the `qwip-atlas` codebase, where layer activations can be thousands of dimensions (e.g. `d_mlp` around 14336), computing boolean masks and taking array reductions (`mean`, `std`) inside a Python `for` loop over dimensions causes massive slow-downs (from 0.3s up to 10s per call).
**Action:** Always prioritize calculating aggregations and slice means over the entire tensor dimension across all rows prior to looping through individual rows, thereby doing operations once via NumPy's highly-optimized C backend.
## 2024-05-18 - Early Slicing and Vectorized Masks for Faster Execution
**Learning:** In PyTorch, applying non-linear activation functions (like `silu`) over huge dense representations with $O(batch\_size \times seq\_len \times d\_mlp)$ scale dimensions is very costly. In `qwip-atlas`, where left-padding puts the last actual token at index `-1` on the sequence dimension, large computation pipelines over extracted tensors should isolate the last token ($O(batch\_size \times 1 \times d\_mlp)$) *before* applying activations to significantly boost runtime. Additionally, constructing explicit per-item sequence masking iteratively was slow, relying on $O(N)$ Python loops which were easily substituted with a single `np.arange` and boolean broadcasting comparison.
**Action:** Always slice PyTorch tensors structurally (when applicable like left-padding scenarios) as early as possible before any mathematical operation to save computation scale. Use NumPy boolean broadcasting instead of per-item Python loops for mask generation.
