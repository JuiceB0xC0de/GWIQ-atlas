## 2024-05-15 - [Vectorizing Array Reductions]
**Learning:** In the `qwip-atlas` codebase, where layer activations can be thousands of dimensions (e.g. `d_mlp` around 14336), computing boolean masks and taking array reductions (`mean`, `std`) inside a Python `for` loop over dimensions causes massive slow-downs (from 0.3s up to 10s per call).
**Action:** Always prioritize calculating aggregations and slice means over the entire tensor dimension across all rows prior to looping through individual rows, thereby doing operations once via NumPy's highly-optimized C backend.
## 2024-05-18 - Python `for` loops vs NumPy/PyTorch Vectorization in Data Extraction Pipelines
**Learning:** In pipelines handling large tensors (e.g. `[B, max_seq_len, d_mlp]`), operations inside Python `for` loops (like applying an activation function element-wise on an un-sliced tensor across batch items, or building a sequence length boolean mask iteratively) scale linearly in python execution time overhead and redundantly execute FLOPs `O(B*S*D)`. Slicing target subsets (like `[:, -1, :]` for last-token left-padded sequence data) *before* expensive operations, and doing so on the batched tensor concurrently, dramatically limits operations to `O(B*D)`.
**Action:** When extracting data from activations, always enforce vectorized slicing prior to computationally heavy steps (activations, matrix multiplications, reshapes) and use NumPy boolean broadcasting instead of python iterations for batched operations.
