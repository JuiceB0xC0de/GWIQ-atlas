## 2024-05-15 - [Vectorizing Array Reductions]
**Learning:** In the `qwip-atlas` codebase, where layer activations can be thousands of dimensions (e.g. `d_mlp` around 14336), computing boolean masks and taking array reductions (`mean`, `std`) inside a Python `for` loop over dimensions causes massive slow-downs (from 0.3s up to 10s per call).
**Action:** Always prioritize calculating aggregations and slice means over the entire tensor dimension across all rows prior to looping through individual rows, thereby doing operations once via NumPy's highly-optimized C backend.
## 2024-05-16 - [Vectorizing Sub-sequence extraction in qwip-atlas]
**Learning:** In `qwip-atlas`, the tokenizer uses left padding (`tokenizer.padding_side = 'left'`). This means the last token of the sequence is ALWAYS at the last index (`-1`) of the sequence dimension. When extracting the last token per sequence across a batch, a common anti-pattern is iterating through each sequence individually with a `for` loop and computing `tensor[batch_idx, slice(-seq_len, None)][-1]`. This causes slow O(batch_size) loops. A massively faster and simpler alternative is to do a vectorized slice: `tensor[:, -1, ...]`. Moreover, since operations like activation functions can be expensive, applying the slice *first* before applying the function dramatically reduces ops from O(B*S*D) to O(B*D).
**Action:** When extracting components in `qwip-atlas`, use vectorized slices for the last token (e.g. `tensor[:, -1, ...]`) instead of depending on computed `seq_lens`. Apply this slice *before* any computational operations like `act_fn` or `.reshape()` to avoid unnecessary computation on padded tokens or tokens that will be discarded.
